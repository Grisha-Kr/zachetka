## 2. Сервер

| Что | Значение |
|---|---|
| Хостинг | AdminVPS (adminvps.ru), личный кабинет на сайте хостинга |
| Тариф | Micro: 2 ядра, 4 ГБ памяти, 60 ГБ диск NVMe |
| Система | Ubuntu 24.04 |
| Имя сервера в кабинете | grisha-server.com (это просто метка, к моему домену отношения не имеет) |
| Имя сервера в Терминале | grisha-server |
| IP-адрес | **168.113.170.172** |
| Вход | пользователь `root`, пароль хранит владелец у себя |

Правила безопасности:
- Пароль root никому не пересылать, помощнику тоже. Помощнику нужен только IP-адрес.
- AdminVPS показывает пароль root в кабинете только 10 дней. Новый пароль можно задать в кабинете, вкладка «Доступ».
- «Доступ для техподдержки» в кабинете AdminVPS оставлен «Запрещён».
- DNS-серверы AdminVPS (ns1.adminvps.ru, ns2.adminvps.net) из приветственного письма **не используются**: домен обслуживает DNS Beget.

### Как подключиться к серверу (Mac)

1. Открыть программу «Терминал».
2. Ввести:
   ```
   ssh root@168.113.170.172
   ```
3. На вопрос `Are you sure you want to continue connecting` (уверены, что хотите подключиться) ответить `yes` (бывает только при первом подключении).
4. На `password:` вставить пароль (Cmd + V) и нажать Enter. Пароль на экране не отображается, это нормально. Если ждать дольше минуты, сервер закроет соединение («Connection closed»), тогда повторить.
5. Если строка начинается с `root@grisha-server`, вы на сервере. Если с `a1234@MacBook-Pro-UH`, вы на своём компьютере.

Полезно знать:
- Если окно Терминала осталось открытым со вчера и в нём `root@grisha-server`, подключаться заново не нужно. Команда `ssh` в таком окне подключает сервер к самому себе.
- Отменить зависшую команду или запрос пароля: **Ctrl + C**.
- Отключиться: `exit` или просто закрыть окно. Сервер и приложения продолжат работать.
- Ошибка «запустите команду от имени root» значит, что команда запущена на Mac, а не на сервере.

## 3. Домен grishaweb.ru

- Куплен в **Beget** (beget.com), там же его DNS (записи, которые связывают адреса с сервером). Хостинг сервера и домен у разных компаний: так проще переехать на другой сервер, достаточно поменять IP в записях.
- Личность владельца подтверждена через Госуслуги (требование закона 569-ФЗ для доменов .ru).

### Текущие записи DNS

| Адрес | Тип | Значение | Зачем |
|---|---|---|---|
| grishaweb.ru | A | 168.113.170.172 | корневой домен ведёт на мой сервер (пока там ничего нет) |
| grishaweb.ru | MX | mx1.beget.com, mx2.beget.com | почта Beget, оставить как есть |
| grishaweb.ru | TXT | запись SPF от Beget | почта, оставить как есть |
| zachetka.grishaweb.ru | A | 168.113.170.172 | приложение «Моя зачётка» |

### Как добавить адрес для нового приложения

1. В Beget открыть управление DNS домена grishaweb.ru.
2. Через меню из трёх точек у домена добавить подзону (поддомен), например `greek`.
3. У новой подзоны поставить **A-запись = 168.113.170.172**. Beget по умолчанию ставит свой IP (например 5.101.152.161), его нужно заменить.
4. Проверить, что A-запись случайно не добавилась корневому домену: у grishaweb.ru должна остаться ровно одна A-запись.
5. Подождать 15-60 минут, пока запись разойдётся.

Интерфейс Beget может меняться. Если не получается, прислать помощнику снимок экрана.

Вариант на будущее: одна запись `*` (звёздочка) типа A на 168.113.170.172 сразу направит на сервер все поддомены, и для новых приложений DNS трогать не придётся. Пока не сделано.

## 4. Как устроен сервер (схема на много приложений)

Задача: 10–15 сайтов и приложений на одном сервере, каждое на своём поддомене (`zachetka.grishaweb.ru`, `greek.grishaweb.ru` и так далее).

- **Caddy** (программа-«диспетчер», ставится из пакетов Ubuntu) принимает все запросы на портах 80 и 443, сама получает и продлевает сертификаты https (Let's Encrypt) и по адресу передаёт запрос нужному приложению.
- Главный файл настроек: `/etc/caddy/Caddyfile`. В нём общие настройки и строка `import /etc/caddy/sites/*.caddy`.
- У каждого приложения свой файл `/etc/caddy/sites/ИМЯ.caddy`.
- **Особенность для России:** в Caddy включён только TLS 1.2 (`protocols tls1.2 tls1.2` в каждом файле сайта) и выключен HTTP/3 (`servers { protocols h1 h2 }` в главном файле). В части российских сетей соединения с TLS 1.3 обрываются по дороге, так советует AdminVPS. Новые сайты настраивать так же.
- Брандмауэр ufw открыт только для портов 22 (SSH), 80 и 443.

### Устройство одного приложения на PocketBase

| Что | Где |
|---|---|
| Папка | `/opt/ИМЯ` |
| Код из GitHub | `/opt/ИМЯ/src` |
| Данные (база, файлы, копии) | `/opt/ИМЯ/pb_data` |
| Настройки | `/opt/ИМЯ/ИМЯ.env` |
| Программа PocketBase | `/opt/ИМЯ/pocketbase` |
| Служба (автозапуск) | systemd `ИМЯ`, системный пользователь `ИМЯ` |
| Внутренний порт | `127.0.0.1:ПОРТ`, снаружи недоступен, только через Caddy |
| Файл Caddy | `/etc/caddy/sites/ИМЯ.caddy` |

### Занятые порты

| Порт | Приложение |
|---|---|
| 8090 | zachetka |
| 8091 | свободен, для следующего приложения |
| 8092 и дальше | свободны |

## 5. Приложение «Моя зачётка»

- Адрес: **https://zachetka.grishaweb.ru**
- Панель администратора PocketBase: **https://zachetka.grishaweb.ru/_/** (логин me@grishakr.ru, пароль выдан при установке и лежит на сервере в `/opt/zachetka/superuser.txt`).
- Код: **https://github.com/Grisha-Kr/zachetka** (ветка main). В репозитории есть `CLAUDE.md` с техническими заметками и `README.md` с инструкцией.
- Старая версия приложения (артефакт Claude): https://claude.ai/artifact/BgoXgvE7VviWd9WysCBC4u. Данные из неё перенесены в новую версию 21.10.2026 (2 заведения, 9 предметов, задание с файлом, 2 сессии, 2 диплома с этапами и заметкой).

### Что умеет

Учебные заведения (с цветом), предметы (статус «Готовлю / Сдал», форма контроля, дата, оценка, преподаватель), задания (что задано, дата выдачи, срок, статус «Не начинал / Приступил / Заканчиваю / Сделал», заметки, файлы PDF и Word), сессии с экзаменами, несколько дипломов (тема, руководитель, сроки, этапы, заметки и идеи, файлы). Главная показывает сроки на 31 день вперёд. Светлая и тёмная тема (кнопка луна/солнце в шапке и блок «Оформление» в профиле). Ставится на телефон и ноутбук как приложение (PWA).

У каждого пользователя свой аккаунт и свои данные. Первый зарегистрированный стал администратором (это я). Остальные регистрируются только по приглашению: «Профиль» → «Приглашения» → ссылка вида `https://zachetka.grishaweb.ru/?invite=КОД`.

### Технически

- **PocketBase 0.40.3**: одна программа, в которой база данных (SQLite), вход, хранение файлов, панель администратора. Выбрана, потому что её легко обслуживать на дешёвом российском сервере. Версия зафиксирована в `deploy/install.sh` (`PB_VERSION`). Версия ещё не 1.0: перед обновлением PocketBase читать заметки к выпуску.
- Интерфейс: обычные файлы без сборки в `pb_public/` (`index.html`, `app.css`, `app.js`), библиотеки и шрифты лежат локально, внешних CDN нет.
- Структура базы и правила доступа: `pb_migrations/`. Менять структуру только **новой** миграцией, старые не править.
- Логика на сервере (приглашения, первый администратор, лимит 500 МБ файлов на пользователя): `pb_hooks/main.pb.js`.
- После правки `app.js` или `app.css` увеличивать `?v=` в `index.html` и версию кэша в `sw.js`.
- Перед каждой выкладкой: `node --check pb_public/app.js` и проверка в браузере на локальном PocketBase.
- Настройки на сервере: `/opt/zachetka/zachetka.env` (`APP_URL`, `OWNER_NAME`, `CONTACT_EMAIL`, `USER_QUOTA_MB=500`, `BEHIND_PROXY=1`). После правки: `systemctl restart zachetka`.

### Как выкладывается доработка

1. Помощник меняет код и отправляет его на GitHub (в репозиторий Grisha-Kr/zachetka).
2. Я подключаюсь к серверу и выполняю:
   ```
   bash /opt/zachetka/src/deploy/update.sh
   ```
3. Жду «Готово: приложение обновлено и работает» и обновляю страницу в браузере (Cmd + R, иногда два раза).

Скрипт перед обновлением сохраняет копию базы в `/opt/zachetka/pb_data/backups` и при любой ошибке запускает приложение обратно.

### Резервные копии

- PocketBase сам делает копию базы каждый день в 3:00 и хранит 14 последних (панель `/_/` → Settings → Backups).
- Хостинг делает еженедельную копию всего сервера.
- Иногда скачивать себе копию: в приложении «Профиль» → «Скачать копию (.zip)». Её же можно загрузить обратно кнопкой «Загрузить копию» (записи добавляются к существующим, одну копию загружать один раз).

## 6. Шпаргалка команд (выполнять на сервере)

```
bash /opt/zachetka/src/deploy/update.sh      # обновить «Зачётку»
systemctl status zachetka                    # работает ли приложение
journalctl -u zachetka -n 50                 # последние сообщения и ошибки приложения
systemctl restart zachetka                   # перезапустить приложение
systemctl status caddy                       # работает ли Caddy (https и адреса)
journalctl -u caddy -n 50                    # ошибки Caddy, например с сертификатом
ls /etc/caddy/sites/                         # какие сайты настроены
cat /opt/zachetka/superuser.txt              # данные входа в панель /_/
```

Выход из просмотра длинного текста (если внизу двоеточие или `(END)`): клавиша `q`.

## 7. Как добавить новое приложение или сайт

Порядок для приложения на PocketBase (например, «Греческий алфавит» с аккаунтами пользователей):

1. Помощник создаёт код в новом репозитории GitHub (я создаю пустой репозиторий на github.com под Grisha-Kr, помощник наполняет).
2. В репозитории делается свой `deploy/install.sh` по образцу зачётки со своими значениями: `APP` (имя латиницей, например `greek`), `PORT` (следующий свободный, 8091), `REPO_URL`.
3. Я добавляю в Beget подзону с A-записью на 168.113.170.172 (раздел 3).
4. Через 15-60 минут подключаюсь к серверу и запускаю установку одной командой, которую даст помощник:
   ```
   curl -fsSL https://raw.githubusercontent.com/Grisha-Kr/РЕПОЗИТОРИЙ/main/deploy/install.sh | bash -s -- АДРЕС me@grishakr.ru "Григорий Кривобок"
   ```
5. Сразу открываю новый адрес и регистрируюсь первым, чтобы стать администратором.
6. Порт и имя записываю в таблицу раздела 4 этого файла.

Для простого сайта без входа и базы (одна или несколько страниц) PocketBase не нужен: файлы кладутся в папку, например `/opt/site-ИМЯ`, а в `/etc/caddy/sites/ИМЯ.caddy` пишется:
```
АДРЕС {
	tls {
		protocols tls1.2 tls1.2
	}
	encode zstd gzip
	root * /opt/site-ИМЯ
	file_server
}
```
затем `systemctl reload caddy`.

Важно для помощника:
- `install.sh` зачётки при каждом запуске заново пишет `/etc/caddy/Caddyfile` (общие настройки). У нового приложения этот файл должен получаться точно таким же, иначе сломаются остальные сайты. Лучше вынести общую настройку Caddy в отдельный скрипт или проверять, что файл уже есть.
- Git на сервере работает с папками от root, а принадлежат они системным пользователям. Поэтому в скриптах использовать `git -c safe.directory=ПАПКА ...` (на сервере уже выполнено `git config --global --add safe.directory /opt/zachetka/src`, для новых папок нужно своё).
- Новые сайты настраивать с TLS 1.2, как в разделе 4.

### Пользователи и срок доступа

В «Профиль» → «Пользователи» (видит только администратор) можно продлевать доступ, ставить паузу и вести заметки об оплате. После срока или при паузе человек может только смотреть и скачивать свои записи. Это задел под будущую помесячную оплату: платёжный сервис будет просто продлевать доступ на месяц. Контакт для продления берётся из `CONTACT_EMAIL` в `/opt/zachetka/zachetka.env`.

### Подключение нейросетей

Каждый пользователь может подключить к своей зачётке ChatGPT, Claude или Perplexity: «Профиль» → «Нейросети», там адрес `https://zachetka.grishaweb.ru/mcp` и инструкции. Работает внутри той же программы PocketBase, отдельной службы и порта не нужно. Вход через окно «Разрешить» (OAuth). Нейросеть может читать, добавлять и менять записи, удалять не может. Подключения видны в профиле, там же кнопка «Отключить».

## 9. Ошибки, на которых уже учились

- «Connection closed» сразу после запроса пароля: пароль не ввели вовремя. «Permission denied»: пароль неверный, ввести ещё раз или задать новый в кабинете AdminVPS.
- «fatal: detected dubious ownership in repository»: git не доверяет папке. Исправлено в скриптах, при повторе выполнить `git config --global --add safe.directory ПАПКА`.
- Команда установки, запущенная на Mac, ничего не делает и пишет «запустите команду от имени root»: сначала подключиться к серверу.
- В Beget быстрое добавление записи может поставить A-запись на корневой домен вместо поддомена. Проверять список записей после добавления.
